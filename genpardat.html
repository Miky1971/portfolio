Generyczny Parser Danych

Zadanie testowe firmy Kamsoft.

Endpoint HTTP w technologii ASP.NET Core Web API / Minimal APIs, który przyjmuje ustandaryzowany ladunek (payload) w formacie JSON, dekoduje i przetwarza przeslane dane, a nastepnie zwraca wynik w ujednoliconej formie (JSON).

  • Technologia: C# .NET
  • Metoda i ścieżka: POST /api/v1/parse-content
  • Format wejściowy: naglówek Content-Type: application/json
  • Payload: { "type": "CSV" | "INTERNAL_JSON", "content": "..." }
  • type - format zawartosci w polu content
  • content - surowe dane zakodowane algorytmem Base64.

Pobierz:

GitHub

Uruchomienie w terminalu:

dotnet run
Serwer (Kestrel) wystartuje na porcie 5091 (zdefiniowanym w Properties/launchSettings.json, profil http) - dokładny adres pojawi się też w konsoli po dotnet run.

Testowanie w drugim terminalu:

dla CSV (content: nazwa,wiek/nJan,30/nAnna,25):
curl -X POST http://localhost:5091/api/v1/parse-content -H "Content-Type: application/json" -d "{"type":"CSV" "content":"bmF6d2Esd2llawpKYW4sMzAKQW5uYSwyNQ=="}"

lub JSON (content: {"nazwa":"Jan","wiek":30},{"nazwa":"Anna","wiek":25}):

curl -X POST http://localhost:5091/api/v1/parse-content -H "Content-Type: application/json" -d "{"type":"INTERNAL_JSON","content":"W3sibmF6d2EiOiJKYW4iLCJ3aWVrIjozMH0seyJuYXp3YSI6IkFubmEiLCJ3aWVrIjoyNX1d"}"

Oczekiwana odpowiedź w obu przypadkach to JSON:

{"status":"Success","qtyRows":2,"totalRows":2,"data":[{"nazwa":"Jan","wiek":"30"},{"nazwa":"Anna","wiek":"25"}]}
